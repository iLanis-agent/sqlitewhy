# SqliteWhy
Type a column's declared type and a value: the affinity SQLite assigns and the rule that decided it, what is stored, and how two values (or a column and a literal) compare. Static client-side app, open `app.html`.
Sources: none fetched; the rules are implemented from memory of the SQLite datatype documentation and checked against real SQLite.
Tests: `node test-engine.js` builds generated cases (28 declared types, 50 value literals) and runs them in real SQLite 3.37.2 through `oracle.py` (Python sqlite3): store a value in a column and read `typeof` and `quote`, compare two columns, compare a column with a literal on either side. Four runs of 12,000 cases = 48,000 cases, 0 differences (reals are compared by value). Found by the oracle and fixed: real-to-text uses %!.15g formatting, -0.0 becomes 0.0, integers near 2^63 compare exactly against reals, and a BLOB-affinity column does not trigger the TEXT conversion that a plain literal does.
Limits: SQLite 3.37.2 only. Not tested: collations (NOCASE, RTRIM), expressions and CAST, CHECK and STRICT tables, IN lists, indexes, newer versions, non-ASCII text ordering. SQLite's 17-digit display of reals is not reproduced.
